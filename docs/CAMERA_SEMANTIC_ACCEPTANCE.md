# 相机三维语义验收

本轮输出目录为新的 `runs/camera_semantic_full`。旧 `camera_full` 的全包完成状态不能代替新语义链路的全包验收。无需训练或微调；模型身份以新运行的 `run.json` 为准。若采用 SegFormer，必须明确其替代 OpenSeeD 的差异，不称为原版 OpenSeeD。

## 验收命令

```bash
.venv/bin/python scripts/verify_camera_semantic.py \
  --run runs/camera_semantic_full \
  --output diagnostics/camera_semantic_qa/semantic_acceptance.json

.viewer-test-venv/bin/python scripts/camera_semantic_browser_qa.py \
  --run runs/camera_semantic_full --frame 135 \
  --output diagnostics/camera_semantic_qa/browser
```

`--allow-partial` 仅检查开发阶段已提交前缀的工程一致性；即使退出码为 0，报告中的完整 bag `accepted` 仍为 false。最终验收必须不带该参数，完成全部 2348 个源时间步。

## 必须满足的工程条件

1. `frames.jsonl` 完整覆盖 0–2347；首末采集时间戳、bag 指纹与 `prepared` 完全一致。不能用 bag 录制时间代替传感器采集时间。
2. 每个时间步有完整的占据、通行、点来源、虚拟视图描述、二维语义缓存。加载 NPZ 使用 `allow_pickle=False`。
3. 每个三维点绑定真实源相机／虚拟视图、深度采样 UV、语义 UV、相机时间戳、类别证据和置信度。类别等于对应源像素，不能被其他相机的中央射线覆写。
4. 深度采样与语义域映射按像素中心缩放。相机点 XYZ 经真实虚拟相机位姿变换，应等于保存的 rig XYZ；射线起点等于该相机光心。
5. 所有标签属于固定车库 registry。车库 `0=wall` 不能解释成 nuScenes `0=noise`；ADE `20=car` 不能作为车库 registry 的数值 ID。类别配色按含义映射。
6. 语义 `255=unknown` 的点仍保留占据几何，其语义置信度和类别证据为零。没有占据预测不代表已确认空闲。
7. 语义已知体素具有正的有效证据支持。体素的类别分数由保存证据的 `max/sum` 独立重算；低于分数／支持门槛的候选类别保持未知，可保留其真实被拒分数供诊断。点级未知证据为零，体素级未知也可能来自多个类别冲突，不要求把实际候选分数伪装成零。体素中心由边界、索引和分辨率计算；当前占据具有实际 source point 的 Gaussian 支持。记录有效 Gaussian 尺度，而不只记录名义 sigma。
8. 所有传感器观测和历史都满足因果时间；ICP 不通过时，不继续使用错误历史，并公开 segment 的局部参考系限制。
9. 相机预测深度不能生成“实测完整净空”类别 3；碰撞占据与射线自由证据互斥。显示筛选不修改保存的几何或通行输出。
10. 新查看器在真实 Chromium WebGL2 中，将源 NPZ 所有体素中心及 registry 颜色上传到实例 buffer；验证全高度／隐藏顶棚、视角、颜色模式、原图与分割图、时间戳及单帧／融合切换。

以上是工程一致性与可追溯性检查，不是三维语义准确率评估。没有三维标注，不报告 OCC mIoU、官方 SOTA、地面真值通行率。

## 独立归因：旧第 135 帧为何只有 7 个车辆体素

本轮实际读取旧 SegFormer 缓存，并使用真实官方 MapAnything 权重重新推理旧第 135 帧（224，stride=3），得到：

| 阶段 | 相机 3 的车辆支持 |
|---|---:|
| 原始鱼眼二维 ADE car 像素 | 66,737 |
| 100°、518×392 校正视图缩小至 224 后车辆像素 | 3,083 |
| MapAnything 深度有效车辆像素 | 1,603 |
| stride=3 有效车辆点，按原始源 UV 关联 | 176 |
| 旧跨视角重投影关联车辆点 | 165 |
| 源 UV 关联得到的当前车辆体素 | 31 |
| 旧重投影关联得到的当前车辆体素 | 27 |
| 旧保存的时间融合车辆体素 | 7 |

17 个源车辆点被旧重投影改标为地面。该问题实际存在，但不是全部退化来源；较窄的垂直校正视野、深度过滤、稀疏采样、将停放车辆一律禁用历史，以及已有地面／墙证据压过当前车辆，都要分别检查。不能将“变成彩色”作为解决车辆退化的证据。

进一步对实际旧点重新计算距其标定源相机的范围：旧重投影的 165 个车点全部在 1.08–1.35m，源 UV 关联的 176 个也全部低于 1.53m；旧融合的 7 个车体素位于 rig 原点约 1.12–1.51m。结合真实图像中的自车车体，它们主要是自车支持，不能作为旧模型对外部停车车辆的识别数量。新正式第 135 帧已保存结果中，车点不超过 2m 为 0、大于 2m 为 185，当前／融合车体素为 26／83。范围分段是诊断，外部车语义仍需图像审查或标注验证；`7→83` 不是准确率。详见 `frame135_baseline_ego_range.json` 和 `full_frame135_consistency.json`。

数值和真实深度输出保存在：

- `diagnostics/camera_semantic_qa/frame135_crop_attribution.json`
- `diagnostics/camera_semantic_qa/frame135_real_depth_attribution.json`
- `diagnostics/camera_semantic_qa/frame135_real_depth_attribution.npz`

另对已有真实二维分割缓存的 9 个时间步测试 100°／110°／120° 与矩形／正方形视野。第 135 帧 stride=3 的车辆采样候选由原始配置 341，增加为 110° 正方形的 781。这里尚未检查新视图的深度有效率；不能把候选增长直接当作三维准确性提升。完整结果在 `rectified_fov_existing_cache.json`。

## 改善测量与解释边界

每个代表时间步同时列出：源二维类别像素、有效深度类别像素、采样点类别数、当前／融合体素类别数、有效支持、置信度和未知比例。确认车辆是否在每阶段保留，确认墙／柱厚度和历史冲突是否改善。更大的类别数、更低未知比例或更长历史都可能伴随错误扩张，不能独立证明质量提高。

类别 softmax 是模型分数，不是标定过的正确概率。历史优先规则、衰减和矛盾射线清理都须写明，并与官方实例／光流运动估计区分。若不接入官方动态模块，要公开这一算法差异。

实际新后端的 8 份预训练推理产物已独立验证逐点源 UV、类别、置信度、top-k 证据和相机到 rig 的 XYZ 变换，记录在 `actual_backend_source_mapping.json`。它们的车类点数大幅上升，但多数是扩展正方形视野内的自车车体。例如第 135 帧 336 分辨率的 6091 个车类点中，5111 个距离源相机不超过 2m；目视 RGB 可见车顶和引擎盖。大于 2m 的 980 个点也只是预测外部车类支持，不能当成准确的停车车辆真值。后续必须考虑固定可见自车区域掩膜，并分别报告近场与远场，不用总车类体素数证明目标识别改善。2m 分段仅用于诊断，不应用作球形几何删除规则，以免删掉真实近场障碍。

已为此次数据采集标注 `configs/camera_ego_mask.json` 的四相机自车可见轮廓，使用 110°、518×518 的固定虚拟视图，并在 0／135／1174／2347 共 16 张真实 RGB 上审查。掩膜只排除可见车体，RGB 保留；边缘保守区域和遮挡之下保持未知，不推测地面。最终配置 SHA256 为 `d616647a4dfa603a68654d2893f829ab2daab176539949230bab378aed17fda7`。第三次必要修正仅沿相机 3 的右侧实际车体／窗边修正原过窄轮廓，来自真实 pipeline 的 68 个近距车辆源 UV 均落入这块可见车体。相机 5 的蓝色分割余边未因类别而被扩大遮掉。证据在 `ego_boundary_evidence`。该掩膜不是车辆三维几何标定，改变安装或虚拟视图后需要重新审查。

同时发现并修复了掩膜缩放的像素域错误：旧 OpenCV 最近邻 mask resize 与语义关联采用的像素中心映射不同，可能在每相机遗留 42–70 个 stride=2 自车候选采样。新相机语义视图显式使用同一像素中心映射；真实域重验四相机均无重叠，报告在 `ego_resize_domain_fixed.json`。最终验收检查所有被掩膜像素的类别为 255、置信度／证据为零，并且不生成三维 source point。旧相机路线的默认缩放行为未修改。

## 官方模型与固定专家选择

官方 OpenSeeD Swin-T 的 793 个预训练参数严格加载，固定 GitHub release asset `105743964`，源提交和 checkpoint SHA256 写入实际元数据。16 张实际 canonical panoptic 推理中，像素类别、分配片段、实际 winning query 的 top-k 类别／分数及拒绝门槛一致，见 `openseed_review/independent_math_review.json`。墙、地面、顶棚及外部车辆可识别，但柱类在该 16 视图中未出现，部分地面和顶棚保持未知。其有效区域已知比例 34.5%–97.2% 是模型覆盖统计，不能当作准确率。

最终配置使用两个真实冻结专家：官方 panoptic 为主，B5 仅在主专家未知且 native/mapped 分数均不低于 0.5 时补充；或当官方为墙、B5 为柱且两个分数均不低于 0.65 时，将人工结构细分为柱。其他官方已知类别不被修改，不跨模型比较分数大小。输出的整个类别／置信度／top-k 行从实际被选专家复制，保留两个完整原始输出、`expert_id` 与 native registry。像素来源取值为 0（官方）、1（未知补充）、2（柱细分）、255（未知），三维点绑定相同源 UV 上的 `semantic_expert_id`。

独立验收不调用后端的组合函数，而重新计算全部选择条件并逐项比对。此组合没有训练，但属于方法适配；不能称为严格原论文复现，也不能以补齐颜色或降低未知比例证明三维语义准确率提高。

截图交付必须同时保留全高度与建筑剖视，并记录视角 JSON、颜色模式、过滤类、网格范围和分辨率。地下车库顶棚遮挡属于真实场景结构；隐藏顶棚仅用于观察，不能宣称原始输出具有更开放的视野。
